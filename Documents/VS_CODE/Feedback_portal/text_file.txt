<audit_checklist_detailed>
Perform an exhaustive line-by-line audit against the following advanced security vectors. Do not summarize; be hyper-specific.

1. Broken Access Control & Privilege Escalation:
   - IDOR (Insecure Direct Object Reference): Can User A fetch, modify, or delete User B's feedback by manipulating the feedback ID in the URL or payload?
   - Privilege Escalation: During registration or profile updates, is it possible for a user to pass `"role": "Admin"` in the JSON body and successfully elevate their privileges (Mass Assignment vulnerability)?
   - Middleware Bypass: Are the route definitions strictly applying the `authMiddleware` and `adminMiddleware`? Is there any edge case where the next() function is called improperly?

2. Advanced Authentication & JWT Flaws:
   - Token Lifecycle: Are JWTs signed with a strong, unpredictable secret? Is there an expiration time set?
   - Brute Force & DoS: Are the `/api/auth/login` and `/api/auth/register` endpoints vulnerable to brute-force credential stuffing? 
   - Mock Kerberos Logic Flaws: Does the Kerberos mock logic inadvertently allow ANY university email to log in without proper verification simulation?

3. File Upload & Storage Vulnerabilities (Multer + Supabase):
   - MIME-Type Spoofing: Is Multer relying solely on the file extension (which can be faked, e.g., `virus.exe.png`), or is it verifying the actual file signature/magic numbers?
   - DoS via Payload: Aside from Multer's 100MB limit, is `express.json({ limit })` and `express.urlencoded({ limit })` configured to prevent massive JSON payloads from crashing the server?
   - Path Traversal: When saving files to Supabase, are the filenames sanitized to prevent directory traversal attacks (e.g., `../../../etc/passwd`)?

4. Injection & Data Integrity:
   - Input Sanitization: Are feedback titles, descriptions, and Google Drive links stripped of malicious `<script>` tags to prevent Cross-Site Scripting (XSS) when rendered on the frontend?
   - Prisma Configurations: Although Prisma prevents SQL injection, are there any `$queryRaw` statements being used unsafely? 

5. Infrastructure & Configuration Security:
   - HTTP Security Headers: Is `helmet` implemented to secure Express headers (HSTS, NoSniff, X-Frame-Options)?
   - CORS Weakness: Is the CORS policy using a wildcard (`*`), or is it strictly locked to the frontend domain? Are credentials allowed safely?
   - Information Exposure: Does the global error handler accidentally leak stack traces, database field names, or Prisma error codes to the client in production?
</audit_checklist_detailed>
